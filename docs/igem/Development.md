# Developing FoundryUI

FoundryUI is designed so new scientific operations can reuse its graph editor, type validation, runtime, event stream, artifact store, and session system. Most extensions require one backend node class and, for an external program, one adapter module.

## Architecture

The Nuxt and Vue frontend renders the BaklavaJS graph and 3Dmol.js viewer. FastAPI provides the REST and Server-Sent Events API. The workflow layer validates graphs and executes them through RyvenCore. Node handlers use biological helpers or external-tool adapters and register their outputs in the artifact store.

The node catalog is generated by the backend and loaded dynamically by the frontend. Ordinary nodes therefore need no duplicated Vue definition.

## Adding a capability

### Adding a node

Create a Python file under `backend/nodes/<category>/` and subclass the relevant category base class. The registry discovers it automatically.

```python
from backend.nodes.scoring.base import ScoringNode
from backend.workflow.catalog import PortSpec as P


class CountStructures(ScoringNode):
    type_name = "CountStructures"
    title = "Count Structures"
    description = "Count structures in an input batch."
    inputs = (P("structures", "Batch Protein", label="Structures"),)
    outputs = (P("score", "Score", label="Score"),)

    @classmethod
    async def execute(cls, ctx, node, inputs):
        # Create and register a Score artifact, then return a TypedPayload.
        ...
```

Every node needs a stable `type_name`, a title, declared ports, and an asynchronous `execute` method. Options can use text, selection, numeric, Boolean, file, or viewer controls. Required values, numeric bounds, and choices are checked before execution.

### Typed payloads and artifacts

Nodes exchange `TypedPayload` objects containing a biological type, item count, artifact identifiers, run-relative paths, metadata, and optional inline data. Reuse an existing type when possible; add a new type and explicit conversions only when its meaning is distinct.

Register every file that should be downloaded, archived, cached, or passed downstream. Use the execution context's text, JSON, and CSV artifact helpers rather than passing absolute paths. Batch nodes must preserve order, item counts, and alignment between structures and scores.

### Connecting an external tool

Place command construction and output collection in `backend/foundry_tools/`. An adapter should:

1. resolve executables and checkpoints from environment variables;
2. validate dependencies and report structured errors;
3. translate typed inputs into the tool's native format;
4. run an argument list through `run_command_streaming`;
5. normalize and register the resulting files.

The RF3, RFD3, ProteinMPNN, and LigandMPNN adapters are reference implementations. This separation allows a node to call a local executable, shared cluster installation, or wrapper script without changing saved workflows.

## External integration

### Packages, web APIs, and compute services

A Python package can be wrapped directly behind a node. Pin its version and translate package-specific errors into FoundryUI errors.

For a web API, keep credentials in environment variables or a secret manager, never in workflows or logs. The adapter should submit work, report progress, download results, handle timeouts and rate limits, and propagate cancellation where supported. The same pattern can integrate Slurm, Kubernetes, or a durable task queue for shared deployments.

### FoundryUI HTTP API

External applications can discover nodes with `GET /api/nodes`, validate graphs with `POST /api/workflows/validate`, create runs with `POST /api/runs`, and follow progress through `GET /api/runs/{run_id}/events`. Additional endpoints manage uploads, manual-node input, sessions, outputs, artifacts, saved results, cancellation, and archives.

This API allows a notebook, laboratory information system, optimization loop, or alternative frontend to use FoundryUI without browser automation.

### Extending standards support

FoundryUI currently supports PDB, mmCIF, FASTA, SMILES, JSON, and CSV. An `SBOLInput` node could translate components, sequences, and features into typed payloads. An `SBOLExport` node could attach designed sequences and run provenance to derived components. The same adapter pattern can add GenBank, GFF, SDF, or registry APIs.

Use official format libraries, preserve stable identifiers, and retain the original document as an artifact.

## Frontend and quality

### Frontend and presets

Frontend work is needed only for a new interaction, visualization, or option control. Shared definitions belong in `frontend/app/utils/`, and custom controls should remain keyboard-accessible and responsive.

Workflow presets live in `frontend/public/workflows/`. Add the `.fuiworkflow` file and register it in `presets.json`. A useful preset should include explanatory note nodes and finish with viewer and save nodes.

### Testing and documentation

Add tests for catalog registration, valid and invalid connections, option validation, typed outputs, artifact creation, and batch alignment. Mock expensive model calls in unit tests, and keep a separate environment-specific smoke test for the real executable.

```bash
source .venv/bin/activate
python -m pytest backend/tests -q
cd frontend
npm run typecheck
npm run build
```

For each node, document its purpose, accepted types, options, outputs, dependencies, resource requirements, and failure modes. When validating a model adapter, compare its result with a direct invocation of the same upstream tool and record tool, checkpoint, hardware, runtime, and dataset versions.
